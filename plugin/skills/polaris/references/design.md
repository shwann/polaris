# 北辰设计要点

改页面前读这一篇。页面源码是插件仓库的 `packages/web`，用 React + TypeScript + Vite 写，分层见 `docs/架构设计.md` 第 4、5 节。构建出来是一个单文件 HTML（`plugin/assets/index.html`），由命令行的 `serve` 提供本机看板，或经 `mirror` 生成线上镜像。外部只从 Google Fonts 加载字体。

| 层 | 目录 | 职责 |
|---|---|---|
| 数据来源 | `src/data/` | 依次尝试：镜像数据槽 → 旧镜像的 `window.POLARIS_DATA` → 本机 `/data.json`（每 3 秒检查一次）→ Artifact 数据库；统一转成 core 的 Snapshot |
| 领域 | `src/domain/` | 纯函数：等待天数、需要你、发版候选、完成比例、搜索、北斗七星与分组的对应和颜色 |
| 状态 | `src/store/` | Zustand：数据快照、界面状态（系统、任务/需求视图、各自筛选、点亮、星图、输入方式、大字）；只在本机存三项选择：`board-system`、`board-input`、`board-proj` |
| 星图引擎 | `src/sky/` | 纯 TS，不依赖 React，自己跑帧循环；页头位置只读 `src/layout/LayoutRegistry` |
| 界面 | `src/components/` | 每个组件一个目录，样式用自己的 `.module.css`；全局状态类只有 `html.proj`、`html.sky`、`.hud`、`.boot` |

## 1. 意象

- **北辰**（北极星）是所有系统的总览，页面名“北辰 · 研发总览”。
- **每个系统是一个星座**，在 `board.json` 的 `systems` 里登记，第一个系统默认叫“北斗”。
- **北斗七星对应七张卡**：

| 序 | 星 | 卡片 / 分组 | 本色 |
|---|---|---|---|
| α | 天枢 | 正式版本（`board.json` 的 `app`） | 青 |
| β | 天璇 | 待开工 `planned` | 灰蓝 |
| γ | 天玑 | 开发中 `doing` | 青 |
| δ | 天权 | 等你或客户回复 `waiting` | 珊瑚红 |
| ε | 玉衡 | 已合入、等发版 `release` | 琥珀 |
| ζ | 开阳 | 已知未验证 `risk` | 紫 |
| η | 摇光 | 已完成 `done` | 绿 |

- **北辰本身是金色**。点亮某颗星时，这颗星、它连着的两段斗线和星名都用这组的本色（`OWN(k)`）。
- **任务是背景里的小星**：按分组聚成星团。缩小时只看到团，放大后同组的星慢慢连成线。
- **星名随缩放变详细**（`sky/draw/starLabels.ts`）：星图里放大不到 2.4 倍只显示编号；2.4～3.6 倍在编号下加标题前 4～12 个字；3.6 倍以上显示完整标题（每行 16 字，最多 3 行）。标签带深色描边，彼此避让，优先显示悬停的星和更亮的星。

## 2. 页面结构（从上到下）

1. **页头**
   - 左边：小字“研发总览”、POLARIS / 北辰、一句副标题、最新动态滚动条（点一下看全部）。
   - 中间：画布里的小北辰徽记（带轨道椭圆）和小北斗。勺子只有七颗星，不画指向北辰的连线。如果按真实方位画连线，勺子会被迫竖起来，所以星图模式里才保持真实方位。
   - 右列：时钟、日期与在线状态，再加三行“关注”：
     - 需要你 N 项（M 项超 3 天）：点一下只看要我做的；
     - 下一版 · N 项候选：点一下打开天枢面板；
     - 完成百分比（完成数/总数）：点一下打开北辰面板。
2. **标签栏**（一行）
   - 左边是系统标签：全部 / 各系统 / ＋其他系统。系统多了以后可以横向滑动，右端渐隐。
   - 右边先是“任务 | 需求”两段切换，再是“✦ 星图 / 大字 / ⛶ 投屏全屏”三个按钮。`#reqs` 对应需求视图，无 hash 或 `#tasks` 对应任务视图；刷新、前进和后退都还原视图。
3. **任务概况**：七张卡，每张卡对应一颗北斗星。点卡片点亮页头那颗星，再点一次熄灭，不会跳到星图。卡片右上角是希腊字母和星名。窄屏时用容器查询依次隐藏：小图标和字母 → 菱形 → 星名。
4. **任务矩阵**：一格一项的色带，下面是“任务分组”和“发版动态”两栏摘要。
5. **筛选与各分组列表**，右侧是动态日志。

### 需求视图

切换只替换标签栏以下的任务主体（卡片、矩阵、摘要、筛选、分组和动态）；页头、时钟、关注、系统标签和星图保持原有行为。

- **概况条**：8 个需求状态数量、P0 数量和漏项总数；点击状态筛出该组，再点可取消。统计始终针对当前系统，不随筛选变化。
- **漏项**：已确认、已排期或开发中但 `taskIds` 为空的需求；`lane` 不是 `done` 且 `reqIds` 为空的任务。`code` 以 `REL` 开头的一次性发版计划任务不算。任务入口复用原有行定位与高亮逻辑，先切回任务视图，必要时清除任务筛选。
- **筛选**：搜索编号、标题、正文，按优先级筛选，只看漏项；与任务筛选相互独立，可重置。
- **需求池**：按 8 个状态分组，组内 P0 → P2、更新时间从新到旧。每行显示编号、标题、优先级、来源、范围、验收已满足/总数和任务编号/进度；任务标签沿用分组本色。展开可见Markdown 正文、逐条验收标准、文档和任务状态。
- **多系统与空状态**：跟随系统选择，“全部”时每行加所属星座。没有需求（包括旧镜像和 Artifact 数据）时显示“还没有需求。对 Claude 说‘记一条需求’，或用 /polaris:req。”。
- **实现位置**：所有分组、排序、搜索、漏项和验收计算在 `src/domain/requirements.ts`；组件及各自样式在 `src/components/Requirements/`；视图与筛选状态在 `uiStore`，通过 `useViewHash` 同步浏览器导航。沿用玻璃面板、切角、现有颜色变量，不增加依赖，不修改星图引擎。

## 3. 画布

- **相机**：相机是 `cam` / `camT` 两组参数，缩放时线宽和星点大小保持不变（`lwk` / `sz`）。
- **两种布局**：`skyK` 在页头小图（0）和全屏星图（1）之间缓动过渡。
- **北斗形状**：北斗用 J2000 真实坐标。`shape(deg, k)` 有两种用法：
  - 大图 `shape(45, 1.5)`，带北辰；
  - 小图 `shape(25, 0)`，只画七星。

  再用 `fit(box, cap, S)` 把形状装进给定区域。**不能把勺子画折**：只做整体旋转和缩放，不单独挪某颗星。
- **页头量位置**：`measureHeader()` 量出 `smallBox`、`smallPole` 和 `veilY`。不要量会溢出的文字范围，要量元素自身的盒子，否则 `smallBox` 会变成空，徽记就不画了。
- **遮罩**：普通模式下，`veilY` 以上的背景星压暗到 0.18，任务星团的编号只在悬停、点亮或匹配筛选时显示。
- **北辰星**（`drawPolaris`）要像照片里真实的星，不要卡通太阳：
  - 白金色星核，外面一小一大两层叠加光晕（`lighter` 混合）；
  - 四道细长衍射芒（一横一竖），斜向两道很淡的短芒；
  - 大气闪烁：用几条正弦叠加出不规则的亮度起伏，颜色在偏蓝和偏暖之间按小台阶跳动；
  - 每隔一阵亮一下，衍射芒随之变长再收回；
  - 系统设置了“减少动画”（`prefers-reduced-motion`）时保持静止。
- **轨道椭圆**：围着北辰，半径用 `Math.max(60, …)` 夹住，过渡时不能变成负数。
- **防止画到零尺寸**：画布宽或高小于 2 时直接返回，否则会在零尺寸帧上出错。

## 4. 交互

- **键盘**：`S` 切换星图，`Esc` 依次关闭卡片、面板、点亮的星和星图；星图里 `+` / `-` / `0` 缩放和复位，方向键在星之间移动。
- **拖动画布**：5px 起拖，范围内 1:1 跟手；按下立即停止旧滑行。最近 80ms 的指针速度按时间覆盖和新近程度加权；松手超过 90px/s 启动惯性，以 350ms 时间常数指数衰减，低于 12px/s 停止，使用实际 dt 的解析积分。触控板滚动不叠加惯性。
- **视差与纵深**：按下、拖动、惯性和边界回收期间冻结 `tx/ty`、`mx/my`，结束后以约 312ms 时间常数恢复。星图平移系数在 `sky/constants.ts`：尘埃 0.35、星云 0.6、底纹 0.8、任务星与北斗 1.0；缩放比例相同。标签、悬停和详情位置都使用 1.0 层；复位清除惯性并还原镜头。看板模式的背景不应用这些分层变换。
- **软边界**：任务星原位（排除拖动偏移）和全部北斗、北辰的包围盒按缩放计算平移范围（`sky/motion/bounds.ts` 的 `KEEP = 0.38`）：内容的远端边缘最多移到距对侧屏幕边 38% 处，所以任何一颗星都能拖到屏幕中间，但整片内容不会拖丢；复位比例下保持原位可达。越界位移用 140px 特征长度的指数橡皮筋压缩；松手以频率 18rad/s 的临界阻尼弹簧回到边界，0.25px / 4px/s 内停止。缩放与触控板平移同样约束。
- **抓起与牵动**：按住任务星即放大 1.25 倍、增加亮度和光晕，隐藏提示框，光标 `grabbing`；空白悬停为 `grab`。保留抓取偏移，不把星心突然吸到鼠标。只沿该星团 `trees` 广度遍历，直接相邻跟随 35%、两跳 15%、更远 5%；每颗星用弹簧追随，有轻微滞后，其他分组不受牵动。
- **连线张力**：相对原长拉伸 150% 达到最高张力；线宽除以 `1 + 张力 × 1.4`，亮度最多增加 70%，颜色向白色偏移最多 70%；张力超过 0.65 时有振幅 7% 的细微闪动，松手随星回位恢复。
- **回弹**：拖动偏移与分组迁移分别计算。回位弹簧频率 14rad/s、阻尼比 0.56，约 12% 过冲，约 0.8～1.2 秒收敛；同组一起回弹。分组迁移保留约 348ms 时间常数的原位缓动。松手位置出现 650ms、最大 72px 的小涟漪，仅视觉效果，不推开其他星。移动不足 5px 仍打开详情。
- **半径与双击**：任务星和主星的抓取 / 悬停屏幕半径为 `clamp(26 × zoom^0.4, 18, 36)px`。双击空白以点击点为中心平滑放大 1.6 倍；双击星打开详情。单指拖动可带惯性；双指以中点捏合，直到全部手指抬起前都不触发惯性或点击。
- **减少动态效果**：`prefers-reduced-motion` 下仍绑定输入，平移、缩放、点击可用；没有惯性、同组牵动、回弹或松手涟漪，星直接回位，环境动画保持静止。
- **星图背景**：看板以现有 0.6 秒过渡淡到 `opacity: 0`，结束后 `visibility: hidden`；退出时立即恢复可见并淡入。保留布局盒子，不能用 `display: none`，以免页头 `LayoutRegistry` 测量失效。
- **触控板 / 鼠标两种模式**：每个人各记一份；没选过时，第一次滚动看起来像触控板就自动切换。
- **大字**：会议室投屏用，字号放大，每段只留一行。“投屏全屏”会同时打开大字，并申请屏幕常亮。
- **记在本机浏览器的选择**（都包在 try/catch 里，存不了也能正常用）：
  - `board-system`：当前系统；
  - `board-input`：触控板 / 鼠标模式；
  - `board-proj`：大字模式。

## 5. 配色与字体

- **单一深色主题**：深夜蓝底，不跟随浅色模式。
- **分组颜色**：`COL` 和 CSS 变量 `--cyan`、`--coral`、`--amber`、`--violet`、`--slate`、`--green`。北辰用金色 `GOLD`。
- **字体**：中文 Noto Sans SC；数字和英文标记用等宽字体。

## 6. 改完必须做的检查

1. **开发**：在插件仓库根目录运行 `pnpm dev`。读数据的请求会转到本机 `polaris serve`（默认 http://127.0.0.1:8790），所以要先起好 serve。
2. **门禁**：`pnpm check`（类型检查、ESLint、Prettier、全部测试）和 `pnpm build` 都要通过；构建前 `umask 022`。测试里有两类专门的检查：
   - **产物级**：每个样式模块都打进了产物，容器查询还在，产物不超过 400KB；
   - **需求视图**：切换和 hash 还原、展开/收起、组合筛选、空状态、多系统与漏项任务定位；领域测试覆盖两类漏项及 REL 例外、状态排序、验收和搜索。
   - **新旧对照**：用 jsdom 把 `history/index.v42.html` 和新产物跑同一份示例数据，内容要一致。
3. **真实画面**：用同一份数据，在 1440、1000、960、375 四个宽度下截图，和改之前对比。浏览器面板隐藏时动画帧不跑，截图不可信，可以改用本机 Chrome 的无界面模式：
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=1440,900 --virtual-time-budget=6000 --screenshot=out.png <地址>
   ```
   逐项检查：
   - 页头不重叠：滚动条、徽记、勺子、右列；
   - 卡片里的字不截断；
   - 点亮的星用本色；
   - 星图开关、Esc 逐层关闭；
   - 控制台没有报错。
4. **生效**：提交构建产物；本机看板刷新即可，线上要重新 `mirror` 并发布。

## 7. 本机编辑与 Markdown

- 只有数据源为本机 serve、页面位于 http://127.0.0.1 或 http://localhost 且获得令牌和页面会话时，才显示编辑控件。内嵌数据槽、`window.POLARIS_DATA`、Artifact 与 `serve --readonly` 均只读，任务视图保持原有布局。
- 任务详情卡、任务列表详情：六个中文分组下拉，0～100 的进度数字框（步进 5，失焦或回车提交）。需求展开区：八个中文状态下拉、逐条验收 ✓ / ○ 按钮；键盘可操作。
- 编辑沿用玻璃面板、颜色变量与现有字号，提交中禁用控件。成功立即接收返回快照，底部提示“已修改：… 撤销”，8 秒消失；撤销也走同一服务层。失败展示中文错误并恢复控件原值；不把失败写入留在快照中。写入期间及写入前发起的旧轮询结果不得覆盖新快照。
- 正文由纯函数解析成节点树，再由 React 渲染；支持 #～#### 标题、段落、无序/有序及嵌套列表、粗体、斜体、行内代码、围栏代码块、引用、链接、简单表格和分割线。HTML 原样作为文字；只允许 http、https、mailto 和 # 锚点，外链带 `target="_blank" rel="noopener noreferrer"`。不使用 HTML 注入、不加依赖。
- Markdown、编辑器、提示条各有独立 CSS Module；代码块和表格在自身容器横向滚动。只读任务视图的 v42 对照仍覆盖原有样式与内容，新增样式单独纳入产物检查。
